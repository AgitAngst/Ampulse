## Context

Сервер Ampulse умеет «зеркало»: `POST /api/v1/mirror` принимает профили, лекарства и приёмы со своими
идентификаторами клиента, повтор той же выгрузки ничего не меняет. Расписания у приложения богаче серверных (интервалы,
циклы, ступени, «по необходимости»), поэтому на сервер уходит результат — конкретные приёмы с временем, а не правила.

## Decisions

1. **Только выгрузка, выключено по умолчанию, только `github`.** `Store.SERVER_SYNC` — `true` в сборке `github`, `false` в
   магазинных; в них строка «Сервер» скрыта, `ServerSync` ничего не запускает, а манифесты `rustore`/`play` по-прежнему
   снимают `INTERNET`. В манифесте `github` `INTERNET` объявлен явно (выгрузка ходит сама, а не «по случаю» от библиотек).
2. **Что выкладывается.** Профили: «Я» (локальный номер 0; имя — строка «Я»/«Me» по языку приложения), свои профили; вид —
   человек → `person`, кошка/собака/другое → `animal`; пояс — системный (без региона — `UTC`). Копии чужого расписания
   (`watchOnly`) не выкладываются: это чужие данные. Лекарства: форма Injection → `injection`, остальные → `pill`; доза — поле
   «дозировка»; заметка; признак архива. Приёмы:
   - плановые: `plannedOn` по схемам не убранных лекарств для дней `[сегодня − 30, сегодня + 14]` в системном поясе; статус
     `pending`, либо `taken`/`skipped` по отметке (`DoseEvent` с тем же лекарством и плановым временем); `taken_at` — время
     отметки только у `taken`; заметка — причина пропуска;
   - отметка плановая, но схема изменилась или стоит на паузе (планового приёма на это время уже нет) — выкладывается как
     плановая со своим плановым временем: отметка не пропадает;
   - внеплановые (`Extra`, «по необходимости», отметки без планового времени): `planned = false`, `planned_at = taken_at`,
     `taken`; внеплановый «пропущено» остаётся `skipped` (приём не принят — выдавать его за принятый нельзя).
   Не выкладываются: аптечка и упаковки, давление, близкие, экстренная карта, место укола, количество, правила схем.
3. **Идентификаторы.** `id = Base64URL(SHA-256(соль ‖ вид ‖ ":" ‖ числа через ":"))[0..22]`. Соль — 16 случайных байт, один
   раз, в приватных `SharedPreferences` (`server_sync`), на сервер не уходит. Вид: `profile`, `med`, `event` (внеплановые, по
   номеру отметки), `plan` (плановые: номер схемы и плановое время в минутах Unix). Детерминированность — повтор не
   задваивает и не требует таблицы соответствий; необратимость — по id нельзя узнать номер записи и связать две выгрузки.
4. **Состояние.** Файл `server_sync_state.json` в `filesDir`: по видам id → `[отпечаток, время приёма, родитель]`; отпечаток —
   SHA-256 содержимого записи. Выкладывается запись, которой нет в состоянии или у которой другой отпечаток. Удаляется то, что
   есть в состоянии, но пропало из построенного набора; приёмы — только внутри окна (вышедшие за его начало со временем
   остаются на сервере). Запись в состояние — по ответу сервера и только для `ok`. Отказ записи насовсем (`bad_*`,
   `text_too_long`) запоминается как `вид/id → отпечаток:код` и не шлётся снова, пока содержимое не изменилось; лекарства и
   приёмы отклонённого профиля не шлются. Прочие отказы (`not_found`, `conflict`…) повторяются в следующий раз. Запись файла
   — через временный файл и переименование. Приёмы старше 400 дней из файла забываются (на сервере остаются).
5. **Сеть.** `HttpURLConnection` + `org.json`, без новых зависимостей приложения; корутины на `Dispatchers.IO`; таймауты 10 с
   на соединение и 30 с на чтение; HTTPS обязателен (`http://` — отказ; в тестах JVM — параметр конструктора); перенаправления
   не выполняются (токен не уйдёт на другой адрес); ответ ограничен 4 МБ. Выгрузка режется по 500 записей каждого вида на
   запрос (предел сервера), порядок: профили, лекарства, приёмы, удаления приёмов, лекарств, профилей. Пароль нигде не
   хранится и не пишется в журнал; токен — в приватных `SharedPreferences` `server_sync_secret`, исключён из переноса на другой
   телефон. 401 на выгрузке → токен стёрт, «вы вышли»; 429 → «подождите N мин»; нет связи, неизвестный хост, чужой
   сертификат — отдельные понятные сообщения.
6. **Запуск.** Вручную («Отправить сейчас»); при открытии приложения, если вошли (не чаще раза в минуту); после изменения
   данных (`ChangeListener` репозитория: отметка, правка лекарства и т. п.) через 30 секунд — одна отложенная задача, изменения
   за это время собираются в один запрос. Закрытое приложение ничего не шлёт. Без WorkManager.
7. **Выход.** «Выйти» — отозвать токен и стереть его, копия на сервере остаётся, состояние сохраняется (повторный вход под тем
   же аккаунтом на тот же сервер ничего не задвоит). «Выйти и стереть копию» — `delete` для всего выложенного (по состоянию),
   затем выход; при отказе (нет связи…) копия и вход остаются.
8. **Экран.** Макета нет (прямо сказано владельцу): собран по образцам «Близкий» (форма, кнопка внизу, поле `FamilyField`,
   `MedNotice`) и строки-перехода «Профили» в «Настройках». Пароль — не в `rememberSaveable`.

## Risks

- Первая выгрузка отправляет и прошедшие неотмеченные приёмы за 30 дней как `pending`. Сервер Ampulse (0.7) приём,
  который при первой выгрузке уже в прошлом, не объявляет (ни напоминания, ни сообщения о пропуске), поэтому рассылки за
  прошлое нет; приёмы, выложенные заранее, объявляются как обычно.
- Смена языка приложения переименует профиль «Я» на сервере.
- Два телефона с одним аккаунтом и разной солью создадут два набора профилей.
