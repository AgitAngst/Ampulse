# Ретранслятор Ampulse (`ampulse-server`)

Версия сервера 0.1.0. Описано по коду на 29.10.2026. Приложение к ретранслятору пока не подключено
(изменение `relay-client`, не начато): документ про сервер, а не про телефон.

Ретранслятор — необязательный свой сервер владельца для близких: пропуск приёма, расписание, экстренная карта
вместо SMS и QR из рук в руки. Приложение полностью работает без него.

## Что он знает и чего нет

- Хранит шифртекст, случайные идентификаторы, размеры и время. Ключей для расшифровки у него нет: ключ пары создаёт
  телефон владельца и передаёт близкому по QR при знакомстве.
- Учётных записей, телефонов, имён и лекарств в нём нет. Доступ к ящику — по токену; сервер хранит только SHA-256 токена.
- Не защищает от: анализа времени и частоты сообщений, владельца сервера, который выключит службу.

## Протокол v1 (HTTPS + JSON, TLS 1.3)

| Запрос | Что делает | Ответ |
|---|---|---|
| `PUT /v1/box/{id}` | создать ящик; тело `{"write_hash","read_hash"}` (Base64URL от SHA-256 токенов) | 201; 204 повтор с теми же хэшами; 409 другие хэши |
| `POST /v1/box/{id}` | положить сообщение; `Authorization: Bearer <write>`, тело — шифртекст до 8 КиБ | 201 `{"seq":N}` |
| `GET /v1/box/{id}?after=N&wait=S` | новые сообщения; `Bearer <read>`; `wait` до 25 с — длинный опрос | 200 `{"messages":[{"seq","at","data"}]}` |
| `DELETE /v1/box/{id}?upto=N` | подтвердить и стереть до `N` включительно; `Bearer <read>` | 204 |
| `GET /v1/health` | живость, ящиков не касается | 200 `{"ok":true,"version":"…"}` |

- Идентификатор ящика — Base64URL от 16 случайных байт. Токен — Base64URL от секретных байт клиента; сервер хранит
  SHA-256 этих байт.
- Неизвестный ящик, чужой токен, токен не той роли, неверный вид идентификатора и пропавший заголовок отвечают
  одинаково: 404 `{"error":"not_found"}`.
- Прочие ошибки: 400; 413 — сообщение больше 8 КиБ; 429 — `rate_limited` (с `Retry-After`) или `box_full`;
  507 — `server_full`; 500.
- Сообщение клиента: XChaCha20-Poly1305, ключ из ключа пары (HKDF-SHA256), тип внутри шифртекста, длина дополнена до
  256 / 1024 / 4096 / 8192 байт. Образец клиента — `server/tests/client_sample.rs`.

## Сроки и квоты

- Сообщение живёт 7 дней, ящик без обращений — 90.
- На ящик: 200 сообщений и 1 МиБ; на сервер — общий потолок; ограничение частоты по адресу (неверный токен списывает
  больше обычного запроса).

## Команды

Бинарник — `/opt/ampulse/ampulse-server`.

| Команда | Что делает |
|---|---|
| `serve` | запускает сервер (его вызывает служба) |
| `install [--port P] [--address A]` | пользователь `ampulse`, каталог, служба systemd, самоподписанный сертификат на 10 лет, порт в `ufw` только если он включён; повтор безопасен: данные, сертификат и настройки остаются |
| `status --json` | `name`, `version`, `running`, `address`, `fingerprint` (SHA-256, hex), счётчики |
| `backup --to ПАПКА` | согласованный снимок базы и сертификата |
| `uninstall` | убирает службу и бинарник; данные остаются |

Выпуск: тег `server-vX.Y.Z` (X.Y.Z = версия в `server/Cargo.toml`), workflow `.github/workflows/server.yml` — по кнопке
(проверки и сборка артефактом) и на тег (плюс GitHub Release: `ampulse-server` x86_64, `ampulse-server-arm64`, `SHA256SUMS`;
оба статические, musl, собраны через zig). Выпуск сервера не «последний» в репозитории — центр находит его по началу
тега (`tag_prefix` в `module.toml`). Теги приложения `vX.Y.Z` workflow не запускают.

Порт по умолчанию — 8740/tcp; если у хостинга есть свой брандмауэр, порт открывается и там.
Ставится и управляется из центра Anvil — манифест `server/module.toml` (сверяется с кодом тестом `tests/manifest.rs`).

## Проверка

`server/`: `cargo fmt --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings`; под Linux — `cargo zigbuild clippy`.
Интеграционные тесты идут на настоящем HTTPS-сервере с самоподписанным сертификатом. Установка на настоящую машину
(`useradd`, `systemctl`, `ufw`, права) не проверялась.
